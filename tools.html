Tools¶

This section is normative.

The commandline tool for validating and analyzing docstrings is waterlint.py. Here is the normative specification what it is supposed to do:

  • Must be invocable from the commandline in a terminal with standard streams stdin, stdout, stderr.

  • Must accept one of the following subcommands { validate, coverage, extract } as first parameter on the commandline.

  • Must accept further options and switches in any order after the subcommand.

  • Must accept an option --out-diag followed by a path.

  • If option --out-diag is present, must write warnings and error messages related to validation to the file specified at option --out-diag.

  • If option --out-diag is not present, must write warnings and error messages related to validation to stderr.

  • Must write warnings and error messages which are not related to validation to stderr.

  • Must accept an option --debug, which may cause generation of debugging data.

  • If there are debugging data, the tool must write them to stderr.

  • Must not write anything to stdout unless specified below.

  • Must accept a switch --fail-on-warning.

  • Must set exit status 0 if no error and no warning was issued.

  • Must set exit status 1 in case of validation error.

  • Must set exit status 1 in case of a warning if --fail-on-warning is enabled.

  • Must set exit status 2 if the tool has been invoked with undefined parameters or an undefinied combination of parameters.

  • Must choose the highest applicable exit status if multiple conditions apply.

For all subcommands which accept --opt (see sections below):

  • If --opt is present, must accept an option --basedir.

  • If --basedir is present, the tool must use its value as base directory for resolving the object passed at --obj.

For subcommand validate:

  • The command must accept options as described in the following list:

    • Must accept an option --obj followed by a Qualified Identifier which can be resolved to a Python module, class, function or method.

    • Must accept an option --in followed by a path to a readable file.

    • Must make sure that options --obj and --in exclude each other.

    • If none of the options { --obj, --in } is present, must read input from stdin and use this as docstring input data.

    • If option --obj is present, must resolve the object and use it as input.

    • If option --in is present, must read the specified file’s content and use the content as docstring input data.

    • Must accept an option --ignore followed by a string which contains a whitespace-separated list of Rule-IDs as specified in Meta.

  • The command must then do the following:

    • If an object is present, must validate its docstring by calling validate_docstring.

    • If only a docstring is available from option --in or from stdin, must parse it and build an Abstract Syntax Tree, by analyzing the profile, creating a docitem_docstring_* instance and calling method parse. If this succeeds, validation is considered successful.

    • Must ignore violations of rules specified by option --ignore if such a rule would lead to a warning.

    • Must not ignore violations of rules specified by option --ignore if such a rule leads to a error i.e. a contract violation.

    • Must catch any exception of type ValidationError from validation ro AST-generation and print its content to stderr.

    • Must print warnings – collected in a tracer – from validation to stderr.

For subcommand coverage:

  • The command must accept options as described in the following list:

    • Must accept an option --obj followed by a Qualified Identifier which can be resolved to a Python module, class, function or method.

  • The command must then do the following:

    • Must validate docstring coverage of the object passed at option --obj, as described in the following cases:

    • If --obj refers to a module, must validate module coverage by calling validate_module_coverage.

    • If --obj refers to a class, must validate class coverage by calling validate_class_coverage.

    • If --obj refers to a callable, must print message to stderr and set exit code 1.

    • Must print warnings – collected in a tracer – from coverage validation to stderr.

For subcommand extract:

  • The command must accept options as described in the following list:

    • Must accept an option --obj followed by a Qualified Identifier which can be resolved to a Python module, class, function or method.

    • Must accept an option --in followed by a path to a readable file.

    • Must make sure that options --obj and --in exclude each other.

    • If none of the options { --obj, --in } is present, must read input from stdin and use this as docstring input data.

    • If option --obj is present, must resolve the object, read its docstring and use this as docstring input data.

    • If option --in is present, must read the specified file’s content and use the content as docstring input data.

    • Must accept an option --section followed by an Identifier.

    • If --section is present, must accept an option --subsection followed by a non-empty string. Informative: shell rules apply for quoting and escaping.

  • The command must then do the following:

    • Must print any string result to stdout.

    • Must interpret the section/subsection passed verbatim, without any transformation, except for stripping whitespace.

    • If --section is not present, must parse the docstring and print the resulting docstring tree to stdout in docstring format by means of function to_string_tree. Informative: We use this for idempotence tests.

    • If --section is present while --subsection is not, must parse the docstring, extract the section subtree by means of function get_tree_of_section and print the resulting subtree by means of function to_string_tree.

    • If --section and --subsection are present, must parse the docstring, extract the subsection subtree by means of function get_tree_of_subsection and print the resulting subtree by means of function to_string_tree.
